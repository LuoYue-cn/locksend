# 安全模型与局限

[English](../SECURITY.md)

不存在“100% 安全”的系统。本文说明 LockSend 设计上能防什么、不能防什么，以及哪些事情还没有被验证。
请和 [PROTOCOL.md](PROTOCOL.md) 一起阅读。

## 能防御什么

| 威胁 | 如何防御 |
|---|---|
| 网络窃听 / 中间人 | 只允许 TLS 1.3（`deploy/nginx/locksend.conf`）；数据本身还做了端到端加密，所以即使 TLS 在中继或 CDN 处终止，内容也不会暴露 |
| 服务器磁盘、数据库、备份泄露 | 只保存密文分块和无法利用的元数据。文件名、大小、类型要么被加密（`enc_meta`），要么只对管理员密封（`sealed_name`）。数据库里存的是 `HMAC(pepper, auth)`；`auth` 里混入了服务器从未见过的 `K_link`，所以无法拿数据库离线验证取件码的猜测 |
| 好奇或恶意的管理员 | 管理界面只能列出 `sealed_name`（只在管理员的浏览器里，用密码封装的私钥解密）、创建和到期时间，并可以删除。管理接口和界面里没有大小、IP、状态历史或下载计数 |
| 链接枚举 | 128 位随机的分享 ID；不存在、已关闭、已过期的分享返回完全相同的结果（`410 gone`）；按客户端的请求频率限制 |
| 在线爆破取件码 | 每个分享有 `max_fails`（3/5/10，默认 5），在串行化的事务里判断；达到上限后销毁（默认）或冻结 24 小时；Argon2id（64 MiB，t=3）让即使拿到 `K_link` 和校验值的人每次离线猜测都代价高昂 |
| 通过 DNS、证书、响应头定位源站 | 中继 + WireGuard 的部署方式（`deploy/relay`、`deploy/wireguard`）；应用本身不向外发请求；`server_tokens off`；`access_log off` |
| 第三方内容 / 追踪 | 没有 CDN、字体、统计或验证码；CSP 为 `default-src 'none'`，只放行本站（Argon2 需要的 `wasm-unsafe-eval` 除外）；端到端测试会断言没有任何请求发往本机以外 |
| 篡改已存储的密文 | 每个分块用 AES-GCM，并把序号和 `is_last` 绑定进 IV/AAD；检查长度；任何一处失败都会中止 |

## 设计上就不能防御什么

1. **被入侵的服务器下发被篡改的 JavaScript。**这是网页端到端加密固有的问题：负责加密的代码本身就是从服务器下载的。
   只能缓解：每个脚本和样式表都带 SRI、严格的 CSP、在 `/build-manifest.json` 公布内容哈希（可以在 `web/` 里用
   `npm ci && npm run build` 复现），并由用户或审计者独立核对这些哈希。在某次请求的那一刻控制着服务器的人，
   仍然可以同时下发另一个页面和另一份哈希清单。
2. 发送方或接收方把链接**和**取件码一起泄露（或者贴在同一个地方）。
3. 终端被攻陷：木马、恶意浏览器扩展、被人偷看屏幕。
4. **流量分析**：观察者能看到上传和下载发生的时间和大致大小（分块大小固定，总长度可见）。
5. **故意销毁。**任何知道分享 ID（URL 里 `#` 之前的部分）的人都可以提交错误的取件码来销毁分享，
   因为服务器没有 `K_link`，分辨不出这是在猜码还是在攻击。这是“输错就销毁”这个设计所接受的代价。
   它是一种拒绝服务，不是信息泄露。如果你更看重可恢复，选择 `freeze_24h`。

## 已知局限与运维注意事项

* **下载完成的确认是客户端自己声明的。**“下载完成后销毁”在浏览器调用 `/complete` 时触发，并且服务器要确认已经向这次下载会话
  发出了每一个分块。恶意客户端可以拉取所有分块但不确认（分享会一直保留到过期或达到最大完成次数），
  但除非它真的拉完了所有分块，否则无法让服务器提前销毁。如果确认丢失（比如浏览器在保存后崩溃），分享会保持可用。
  手机浏览器和回退到内存保存的场景下，页面无法确认浏览器是否真的把文件存下来了，只能在用户点“保存文件”之后上报完成。
* **服务端密钥。**`server_pepper` 应该来自环境变量（`LOCKSEND_PEPPER`）。如果使用兜底方式生成到 `data/secrets/pepper`，
  整个服务器磁盘被攻陷时它也会一起泄露；仅数据库泄露仍然拿不到。丢失 pepper 会让所有已有分享和管理员登录失效。
* **TOTP 密钥**用从 pepper 派生的密钥加密后保存，但服务器必须能解密它才能验证动态码。
  服务器被完全攻陷时，应当认为第二因素也已暴露。
* **管理员密码丢失无法找回。**私钥是用只在浏览器里由密码派生的密钥封装的，服务器无法重置。重新安装会生成新的密钥对，
  旧的密封文件名将永远读不出来。
* **访客地址。**应用本身不保存：nginx `access_log off`，PHP-FPM `access.log = /dev/null`。限速用的桶是“地址 + 只存在于 Redis 里的随机密钥”
  的 HMAC（内存中，`save ""`，最多 2 天后过期），过期后无法还原。在中继之后，所有访客共用隧道地址，所以这些限制实际上变成全局限制，见
  `deploy/relay/README.md`。
  **注意：**如果你用宝塔面板，它的“网站监控报表”会通过站点配置里的 `access_log syslog:…site_total` 记录每个请求，
  包括 Cloudflare 转发来的访客真实 IP，必须为这个站点关闭。
* **Redis 丢失**（重启）会使正在进行的上传/下载会话、限速计数和管理员会话失效；客户端可以续传上传（分块在磁盘上），
  并重新解锁下载。分享本身存在数据库里。
* **内存和设备限制。**64 MiB 的 Argon2id 在内存很小的手机上可能失败。没有可用 service worker 的浏览器会退回到把整个文件放进内存
  （文件大小限制为 500 MB）。
* **SQLite 的删除。**行会被清空（`secure_delete = ON`，秘密字段置空），但被删除的数据可能残留在旧备份和文件系统快照里。
  密文文件的删除是普通的 `unlink`；请使用加密的磁盘卷。
* **服务器必然能看到的元数据：**分享 ID、创建和到期时间、分块数（分享存在期间约等于文件大小，误差在 4 MiB 以内）、
  所选的策略（最大错误次数、错误后的动作、是否下载后销毁）以及请求的时间。

## 验证情况（测过什么、没测过什么）

在本仓库里测过的内容（都可以重新运行，见 [DEPLOY.md](DEPLOY.md) 第 10 节）：

* 带固定测试向量的 JS 密码学单元测试：17 项。
* PHP 测试：51 项，在 **PHP 8.3.35** 上运行（用官方源码编译，带 FPM、`sodium`、`pdo_sqlite`、`pdo_mysql`、`intl`
  和 PECL 的 **`redis` 6.3.0 扩展**）。整套测试在 SQLite 和真实的 **MariaDB 11.4.5** 服务器上都通过（每个测试用独立的空数据库）。
  其中包括：用独立实现（libsodium / `hash_hkdf` / OpenSSL）重新计算协议测试向量；用真实的并行进程在同一个分享上竞争猜码
  （`ConcurrencyTest`；去掉事务后在两种数据库上都会失败）；用真实的 redis-server 通过 unix socket 和 TCP、分别经过 ext-redis 与内置客户端
  测试 `RedisKv`；以及 500 MB 的文件大小限制。
* PSR-12：`vendor/bin/phpcs` 报告 0 个错误、0 个警告（仅测试文件免除行长度警告）。
* 生产用的 nginx 文件（`scripts/check-nginx-tls.sh`）：用临时自签证书 `nginx -t` 通过；实际握手协商出 TLS 1.3，
  **TLS 1.2 被拒绝**；HSTS/CSP/nosniff/COOP 响应头存在；不暴露 nginx 版本；HTTP 跳转到 HTTPS；源码、vendor、数据目录和点开头文件的路径返回 404。
* 无头 Chromium 端到端测试，**48 项检查，经过真实的 PHP-FPM 8.3 主进程/进程池，加载随仓库提供的
  `deploy/php-fpm/locksend.conf`**（unix socket、`clear_env`、`open_basedir`、从进程池的 `env[]` 读取 pepper），使用随仓库提供的
  nginx location/header/fastcgi 文件，Redis 通过 unix socket 并使用 ext-redis。覆盖：安装流程及其封闭；多分块上传下载并比对 SHA-256、
  service worker 流式下载；上传在 4 块中的第 2 块后中断并续传、不重发已存的分块；空文件；下载后销毁；取件码错误销毁；缺少或错误的 `K_link`；
  管理员解密文件名和删除；500 MB 限制（页面上显示，500 MB + 1 字节的文件在发出任何请求前就被拒绝）；一个 **490 MB 的文件**
  （117 个分块，磁盘上的密文大小精确吻合）上传、流式取回并解密，SHA-256 一致，PHP-FPM 内存不变，确认下载后密文被删除；
  数据目录里没有任何明文的名字、取件码或密钥；没有任何第三方请求。同一套测试在更简单的 `php-cgi` 环境上也通过。
  在那次运行之后，又新增了下载路径的用例，只在 `php-cgi` 环境上运行（共 55 项检查）：另存为窗口；下载管理器对 `/dl/<key>` 返回 404 或错误
  （页面会回退到别的保存方式）；另存为窗口立即返回“已取消”；用户关闭了窗口；以及手机浏览器配置下，文件解密后通过单独点一次“保存文件”来保存。
  这些新用例已确认在修复前的代码上会失败。
* `scripts/audit_privacy.sh` 静态检查（已验证在注入违规内容时会失败）。

这些运行中发现并修复的问题：随仓库提供的 FPM 进程池文件里，没加引号的 `base64:…=` pepper 会让 PHP-FPM 拒绝启动；`RedisKv` 无法解析
随仓库配置使用的 `unix:///…` 套接字地址；一个测试辅助代码需要 `intl`，而 PHP 8.3 默认不启用它；一些手机浏览器提供的另存为窗口会立即返回“已取消”，
下载管理器也会劫持流式下载，这让真实部署上的下载失败（见 [QUESTIONS.md](QUESTIONS.md) 第 11 条）。

没有测试 / 不作保证的内容：

* Docker 镜像和 `docker-compose.yml`（测试机器上没有 Docker）、systemd 单元、中继（`nginx-stream.conf`）、WireGuard 和 nftables 规则。
  证书的申请和续期（只用过自签证书）。
* 以 root 身份运行 FPM 并切换到 `www-data` 用户（FPM 是以普通用户运行的，所以 `user`/`group` 被忽略），以及 `/var/lib/locksend` 真实的文件系统权限。
* 超过 500 MB 的文件现在不再接受。在加限制之前，一次 4.5 GiB 的上传成功了，但上传过程中浏览器内存增长了约 3.9 GiB，原因没有深究
  （见 QUESTIONS.md 第 16 条）。
* 浏览器完全重启后的续传（页面内的续传测过了；新页面无法接着旧上传继续，因为上传令牌和密钥只存在那个页面的内存里，这是设计如此）。
* 非 Chromium 内核的浏览器，以及内存很小的设备。
* 没有经过任何第三方的安全评审。
