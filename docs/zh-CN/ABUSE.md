# 滥用处理

[English](../ABUSE.md)

匿名的端到端加密服务无法检查内容，所以滥用处理依赖限制措施，以及运营者删除分享的能力。
在向公众开放服务之前，请先确定你的政策和法律立场。

## 运营者能做什么、不能做什么

* **能：**在 `/admin` 里列出有效的分享（解密后的文件名、分享 ID、日期），并删除任意分享。删除会立刻移除密文并清空元数据；
  之后这个分享和任何不存在的分享一样返回 `410`。
* **不能：**读取内容、查看大小、上传者或下载者的地址、下载历史。除了分享 ID、时间戳、分块数和策略标志之外，没有任何数据可以交出。
  请在你的服务条款里如实说明这一点。
* 手里有完整链接和取件码的举报人，可以把它们发给运营者；运营者在举报人同意的前提下，可以用普通的下载页面自己解密并判断文件。

## 内置的限制

| 控制项 | 默认值 | 位置 |
|---|---|---|
| 每个客户端桶新上传次数 | 20 次 / 小时 | `LOCKSEND_CREATE_PER_HOUR`、`UploadApi::reserve` |
| `/api/` 的请求频率 | 30 次/秒，突发 60（按地址，保存在 nginx 内存里） | `deploy/nginx/locksend.conf` |
| 最长有效期 | 30 天 | `LOCKSEND_TTL_MAX_DAYS` |
| 未完成的过期上传 | 24 小时后清除 | `bin/cleanup.php` |
| 磁盘保护 | 剩余空间低于 512 MiB 时拒绝上传 | `LOCKSEND_MIN_FREE_BYTES` |
| 分块大小 | 恰好 4 MiB（+16），服务端校验 | `UploadApi::putChunk` |
| 文件大小 | 500 MB（实现为最多 120 个分块；`413 file_too_large`） | `LOCKSEND_MAX_FILE_BYTES`、`UploadApi::create` |
| 管理员登录 | 每个桶 15 分钟 8 次，全局 15 分钟 40 次，TOTP 只能用一次 | `AdminApi::login` |

单个文件默认限制在 **500 MB**（`LOCKSEND_MAX_FILE_BYTES`；见 [QUESTIONS.md](QUESTIONS.md) 第 16 条）。请把它和磁盘保护、文件系统配额结合使用；
面向公众部署时，可以考虑调低 `LOCKSEND_TTL_MAX_DAYS`、调严 `LOCKSEND_CREATE_PER_HOUR`。在中继或 Cloudflare 之后，所有客户端共用一个桶，所以按客户端的限制会变成全局限制。

## 建议的处理流程

1. 接收举报（用你公布的一个地址；不要收集超出需要的信息）。
2. 如果举报人提供了链接和取件码，在一个一次性的浏览器配置里下载并查看文件；否则根据 `/admin` 里显示的文件名判断。
3. 如果违反你的政策，在 `/admin` 里删除这个分享；只记录分享 ID 和日期。
4. 如果收到法律上的要求，只提供实际存在的内容（见 [PRIVACY.md](PRIVACY.md)）；不要声称系统具备它没有的能力。

## 没有提供的功能

没有自动的内容扫描（端到端加密下不可能），没有用户账号，没有针对上传者的黑名单（拿不到身份信息），没有验证码（不允许使用第三方服务）。
