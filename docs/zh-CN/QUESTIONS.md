# 遗留问题与已做的决定

[English](../QUESTIONS.md)

当需求文档没有说明、含糊或相互冲突时，下面每一项都选择了更安全的方案并继续推进。每一项运维者都可以重新决定。

1. **需求文档在 `shares` 表（第 4 节）之后被截断，并且提到了一个“第 14 节”。**
   任务文本在表结构中间结束（`status ... expir`），第 14 节也没有提供。决定：`status` 取值为
   `uploading | ready | downloading | burned | destroyed | expired`；表结构的其余部分在 `server/migrations/001_init.sql`。
   “第 14 节”大概想表达的威胁模型和局限，写在 [SECURITY.md](SECURITY.md) 里。
2. **PHP 版本。**文档开头写 PHP 8.1，技术栈一节写 8.3。决定：`composer.json` 要求 `>=8.3`，代码使用
   `declare(strict_types=1)`。开发最初是在 PHP 8.5 命令行上进行的；之后又在用源码编译的 PHP 8.3.35（带 FPM）上重新运行了整套测试，
   见 SECURITY.md 的“验证情况”。
3. **安装流程。**除了“有一个安装完成后自动封闭的安装页”之外没有更多说明。决定：在服务器上生成一次性安装令牌
   （`php server/bin/admin-setup-token.php`，只保存它的 SHA-256）；安装页检查环境、输入令牌、设置管理员密码（在浏览器里处理）并绑定 TOTP。
   成功后写入 `data/installed.lock`、删除令牌，`/install` 和所有安装接口都返回 404。没有令牌就无法安装，
   所以先于你访问到全新服务器的陌生人无法接管它。
4. **管理员认证。**没有说明。决定：密码（浏览器里做 Argon2id，只发送一个独立的 HKDF 输出）加 TOTP（`spomky-labs/otphp`），
   HttpOnly + SameSite=Strict 的 Cookie，修改类请求带 `X-LockSend: 1` 头，登录有频率限制，TOTP 动态码只能用一次。
5. **只凭分享 ID 就能销毁。**服务器分辨不出是谁在猜码，所以任何知道 URL 路径的人都可以耗尽尝试次数（见 SECURITY.md）。
   按任务要求接受（“故意输错是保护性结果”）。`freeze_24h` 是替代方案。
6. **访客 IP 与限速。**“不记录 IP”和“限制猜码频率”相互冲突。决定：按分享计数的失败次数完全不使用 IP；粗粒度的按客户端请求限制，
   使用“地址 + 只存在于 Redis 内存里的随机密钥”的 HMAC（最多 2 天）。在中继之后所有访客看起来一样，所以退化为全局限制。
7. **下载完成的确认。**“客户端确认完成”可以被伪造。决定：服务器只有在已经向该会话发出每一个分块（用 Redis 位图记录）之后才接受确认，
   并在 SECURITY.md 里如实说明它仍然是客户端自己声明的。
8. **`max_completions`。**默认 1，按分享保存；界面不提供其他取值（接口接受 1–100）。
9. **管理员可见的数据。**需求只允许看文件名和删除。决定：列表显示解密后的文件名、分享 ID 和两个日期，不显示大小、IP、状态或次数。
   `chunk_count` 会保存（提供下载需要）但不对外暴露。
10. **墓碑记录。**已关闭的分享保留一行秘密字段已清空的记录 7 天（这样返回的仍是 `410`），之后由 `bin/cleanup.php` 删除。
11. **下载的保存方式。**按顺序尝试三种：(1) 浏览器的另存为窗口（File System Access API，基于 Chromium 的浏览器），把解密后的分块直接写入所选文件；
    (2) 通过 service worker 做流式下载（`/sw.js`、`/dl/<随机密钥>`），内存占用固定；(3) 在内存里组装 Blob（文件限制在 500 MB 以内，所以可以接受）。
    有用户反馈过一个问题（“下载已取消”，并且浏览器下载列表里出现 404）：当下载管理器类扩展或浏览器自己拿着 `/dl/<密钥>` 去向服务器重新请求时，
    服务器上根本没有这个地址。现在页面会发现浏览器在几秒内没有开始读取流式下载、或者下载被取消，然后自动换到下一种方式。
    关闭另存为窗口会直接停止，不会再自动发起第二次下载。手机和应用内置（WebView）浏览器的另存为窗口经常存在但已损坏
    （会立刻以“已取消”拒绝），所以在手机上页面会先在内存里解密，并显示一个“保存文件”按钮，由用户重新点一次来保存；
    在电脑上，如果 0.6 秒内就收到 AbortError，会当作“窗口根本没出现”，改用下一种方式。
12. **zxcvbn。**自定义取件码需要它，但它约 800 KB。决定：单独做成带内容哈希、带 SRI 的文件，只在输入自定义取件码时才懒加载，
    默认页面保持很小。
13. **CSP 里的 `wasm-unsafe-eval`。**编译 Argon2 的 WASM 模块需要它。不允许 `unsafe-eval` 或 `unsafe-inline`。
14. **部署目标。**nginx/TLS 1.3 的文件、PHP-FPM 进程池文件和 Redis 设置都已经实际运行并测试过（见 SECURITY.md）。
    Docker 镜像、`docker-compose.yml`、systemd 单元、中继和 WireGuard 文件只是提供了，从未执行过。
15. **语言。**界面是中文（任务使用的语言）；文字直接写在 `web/src/` 里，尚未抽出成多语言文件。
16. **文件大小限制（由产品负责人改动）。**最初的决定是“文件大小不设上限”。在一次 4.5 GiB 的浏览器测试中发现上传页面的内存随文件大小增长
    （Chromium 中约增加 3.9 GiB）之后，负责人决定改为**单文件 500 MB 的限制**，不再追查这个问题。实现方式：服务器看不到明文大小，
    所以把限制实现成分块数上限，`chunk_count <= ceil(LOCKSEND_MAX_FILE_BYTES / 4 MiB)`（默认的 500 000 000 字节对应 120 个分块），
    超出时返回 `413 file_too_large`；超出声明数量的分块序号本来就会被拒绝。上传页面从 `/api/config` 读取 `max_file_bytes`，显示出来，
    并在联系服务器之前就拒绝超大的文件。被修改过的客户端仍然可以在同样的 120 个分块里声明一个更小的文件，这是无害的：
    存储的密文永远不会超过 120 × (4 MiB + 16 B)。分块加密、断点续传和流式下载都没有变化。500 MB 以上出现的内存增长没有进一步调查。
