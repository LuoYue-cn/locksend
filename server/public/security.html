加密文件分享

安全说明与局限

不存在绝对的安全。下面如实说明这个服务做了什么、没做什么。

做了什么

  • 文件、文件名、大小和类型都在你的浏览器里加密，服务器只保存密文。
  • 下载需要两样东西：链接 # 之后的密钥，以及单独告知对方的取件码。只拿到其中一样无法解密。
  • 取件码连续输错到上限后，分享会被销毁（或冻结 24 小时，取决于发送者的设置）。
  • 下载完成后默认自动销毁分享。
  • 服务器不记录访问者 IP；页面不加载任何第三方资源。

没有防御的情况

  • 服务器被入侵后替换了网页脚本。这是网页端到端加密固有的弱点。我们用 SRI、严格的 CSP 并公示前端构建哈希（build-manifest.json）来降低风险，但无法消除。
  • 你或对方自己泄露了链接和取件码。
  • 设备被木马或恶意扩展控制。
  • 流量分析：上传和下载的时间与数据量对网络观察者是可见的。
  • 任何持有链接的人故意输错取件码，可以让文件被销毁。这是为了防止暴力猜测而接受的取舍。
